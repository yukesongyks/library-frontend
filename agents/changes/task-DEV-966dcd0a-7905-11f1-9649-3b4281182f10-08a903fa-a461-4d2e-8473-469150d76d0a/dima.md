# 成本统计报表 需求澄清文档 (dima.md)

> 基于 brainstorming 技能产出，用于澄清「成本统计报表」功能需求与范围，作为后续实施计划与系分设计的基础。

## 1. 需求概述

开发一个**成本统计报表**系统，用于统计企业各项成本支出情况。前端新建「成本统计分析页面」与「Dashboard」，支持按照不同维度展示与统计数据，并支持报表导出。

### 1.1 核心目标
- 提供企业成本支出的统一可视化视图（Dashboard + 多维度分析页）。
- 支持按 部门 / 项目 / 业务线 / 人员 / 月份 / 季度 / 年度 多维度交叉统计。
- 涵盖两大成本域：**人力成本**（开发、测试、产品、运维）与 **项目成本**（预算、实际消耗、预算占比、预计超支金额）。
- 支持报表导出（前端触发，后端生成）。

## 3. 功能范围（YAGNI 裁剪后）

### 3.1 前端 (library-frontend)
1. **成本统计 Dashboard 页**
   - 成本总览卡片：总人力成本、总项目成本、总预算、预计超支总额。
   - 趋势图：按月份/季度/年度展示成本趋势，支持同比/环比多线对比。
   - 维度分布图：按部门/业务线/人员展示成本占比。
2. **成本统计分析页**
   - 多维度筛选：部门、项目、业务线、人员、时间范围（月份/季度/年度）+ 对比去年同期/上期。
   - 人力成本明细表：按角色（开发、测试、产品、运维）分解。
   - 项目成本明细表：项目预算、实际消耗、预算占比、进度%、预计最终成本、预计超支金额。
3. **Excel 导入页**（成本统计分析页内入口）
   - 模板下载、文件上传、导入结果预览（成功/失败条数与错误明细）。仅管理员可见。
4. **报表导出**
   - 导出按钮提供格式选择（Excel / CSV），调用后端接口后 Blob 下载。仅管理员可见。

### 3.2 后端 (library-backend)
1. **数据模型**：部门、项目、业务线、人员、人力成本记录、项目成本记录（含 `progress_percent` 字段）。
2. **统计查询 API**：按维度聚合返回 Dashboard 概览与明细数据，含同比/环比计算。
3. **Excel 导入 API**：`POST /api/cost/import`，解析 .xlsx，校验后写入数据库。
4. **报表导出 API**：`GET /api/cost/export`，支持 `format=xlsx|csv`。

## 4. 关键维度与数据字段

### 4.1 统计维度
| 维度 | 说明 | 示例值 |
|------|------|--------|
| 部门 | 成本归属部门 | 研发部、测试部、运维部 |
| 项目 | 成本归属项目 | 项目A、项目B |
| 业务线 | 成本归属业务线 | 信贷线、支付线 |
| 人员 | 成本归属个人 | 张三、李四 |
| 月份 | 自然月（时间序列主键） | 2026-01 |
| 季度 | 自然季度 | Q1/Q2/Q3/Q4 |
| 年度 | 自然年 | 2026 |

### 4.2 人力成本字段
- 角色：开发（DEV）、测试（QA）、产品（PM）、运维（OPS）
- 成本项：人力成本金额、人月数、人均成本

### 4.3 项目成本字段
| 字段 | 说明 | 默认值/计算口径 |
|------|------|----------------|
| 项目预算 | 项目总预算金额 | 导入值，DECIMAL(12,2) |
| 实际消耗 | 项目已消耗成本 | 导入值，DECIMAL(12,2) |
| 进度% | 项目当前完成进度 | 导入值，`progress_percent` DECIMAL(5,2)，默认 0 |
| 预算占比 | 实际消耗 / 项目预算 | 计算字段，预算=0 时返回 null |
| 预计最终成本 | 进度>0: 实际消耗/(进度%/100) | 计算字段 |
| 预计超支金额 | 预计最终成本 - 预算 | 计算字段，>0 则标记超支 |

## 5. 跨仓接口契约（草案，待系分细化）

### 5.1 统计查询接口
- `GET /api/cost/dashboard` — Dashboard 概览数据（含同比/环比增长率）
- `GET /api/cost/human/list` — 人力成本明细（支持维度筛选）
- `GET /api/cost/project/list` — 项目成本明细（支持维度筛选，含预计超支计算）
- `GET /api/cost/aggregate` — 多维度聚合统计

### 5.2 导入接口
- `POST /api/cost/import` — 上传 .xlsx 文件，`type=human|project`，返回导入结果（成功/失败条数 + 错误明细）

### 5.3 导出接口
- `GET /api/cost/export?type={human|project|dashboard}&format={xlsx|csv}&{维度参数}` — 返回文件流

## 6. 仓间对齐点
1. **维度枚举一致性**：部门/项目/业务线/人员/时间粒度的编码与取值需前后端统一。
2. **成本域字段对齐**：人力成本角色枚举（DEV/QA/PM/OPS）、项目成本计算口径（预算占比、超支判定）前后端一致。
3. **导出文件格式**：前端请求参数与后端生成格式（Excel/CSV）需对齐。
4. **时间维度换算**：季度/年度与月份的映射规则前后端一致。

## 7. 澄清决策记录（含默认值规格）

| 编号 | 问题 | 决策（默认值规格） | 轮次 |
|------|------|---------------------|------|
| Q1 | 业务定位 | library → 综合管理平台演进，成本统计为首业务域，平台级可扩展架构（统一鉴权+组织树+菜单路由框架） | R1 |
| Q2 | 前端技术栈 | Vue 3 + TypeScript + Vite + Element Plus + ECharts，SPA 单页应用，无 SSR | R2 |
| Q3 | 后端技术栈 | Java + Spring Boot 3 + Maven 多模块（platform-base + cost）+ MyBatis-Plus | R2 |
| Q4 | 数据来源 | Excel 导入（Apache POI/EasyExcel 解析 .xlsx），无录入页面，预留外部对接 Service 抽象层 | R3 |
| Q5 | 导出格式 | Excel(.xlsx, EasyExcel, 含表头样式+合计行) + CSV(UTF-8 BOM, 原始明细)，无 PDF | R4 |
| Q6 | 权限范围 | 两角色 `ADMIN`/`USER` 硬编码；ADMIN=查看+导出+导入，USER=仅查看；按部门/业务线数据级隔离；Spring Security + JWT；预留 RBAC 升级 | R5 |
| Q7 | 历史数据 | 同比(YoY)+环比(MoM/QoQ)对比分析；`cost_period` 月份字段为时间序列主键；不物理删除历史；导入校验月份唯一 | R6 |
| Q8 | 预计超支口径 | 主算法：`estimated_final_cost = actual_cost / (progress_percent / 100)`；兜底（进度=0/NULL）：`estimated_overrun = actual_cost - budget`；不引入蒙特卡洛/多情景预测 | R7 |
| Q9 | 部署形态 | 本期仅本地开发环境（前端 Vite dev proxy → 后端 8080；后端 dev profile + 本地 DB）；不引入 Dockerfile/CI-CD/Nginx，后续迭代再定 | R8 |

### 7.1 各决策影响摘要
- **Q1 架构**：平台基座（统一鉴权、组织树、菜单/路由框架）+ cost 模块插件化接入；Maven 多模块（platform-base + cost）。
- **Q2 前端**：Vue 3 + Vite 脚手架，Element Plus（表格/筛选/表单），ECharts（趋势图/占比图），Vue Router 多级路由。
- **Q3 后端**：Spring Boot 3 + Maven 多模块，MyBatis-Plus 数据访问，统一异常处理与响应封装。
- **Q4 导入**：`POST /api/cost/import`，EasyExcel 解析，人力成本模板（部门+项目+业务线+人员+月份+角色+成本金额）、项目成本模板（项目+部门+业务线+月份+预算+实际消耗+进度%）。
- **Q5 导出**：`GET /api/cost/export` 新增 `format` 参数（xlsx/csv）；Excel 含表头样式/合计行，CSV 纯文本无样式；Maven 新增 `easyexcel` 依赖。
- **Q6 权限**：`role_code` = `ADMIN`/`USER`；后端查询按用户部门/业务线 ID 过滤（MyBatis-Plus 拦截器），管理员跳过过滤；前端导出/导入按钮仅 ADMIN 可见。
- **Q7 历史数据**：同比 = (本期 - 去年同期) / 去年同期 × 100%；环比 = (本期 - 上期) / 上期 × 100%；导入校验月份不可重复。
- **Q8 超支**：项目成本表新增 `progress_percent` 字段；Dashboard 超支卡片 = Σ(所有超支项目 estimated_overrun)；导出含进度%/预计最终成本/预计超支金额列。
- **Q9 部署**：Vite dev server + proxy 转发 `/api` → 8080；Spring Boot dev profile + 本地 DB；不引入运维基础设施。

## 8. 异常兜底方案

### 8.1 Excel 导入异常
| 异常场景 | 兜底策略 |
|----------|----------|
| 模板格式错误（非 .xlsx / Sheet 名不符） | 拒绝整批，返回 `{success: 0, failed: N, errors: [...]}` |
| 数据校验失败（金额非负、月份格式、维度枚举非法） | 逐行记录错误，合法行成功导入，返回成功/失败条数 + 错误明细 |
| 重复数据（同部门+项目+人员+月份） | 覆盖更新（以最新导入为准），返回覆盖提示 |
| 文件过大 / 解析超时 | 限制单文件 ≤ 10MB，解析超时 60s 中止并返回错误 |

### 8.2 统计查询异常
| 异常场景 | 兜底策略 |
|----------|----------|
| 无数据 | 返回空结构（非报错），前端展示「暂无数据」占位 |
| 同比/环比除零（去年同期/上期 = 0 或无数据） | 增长率返回 null，前端显示「-」 |
| 查询超时 | 设置 30s 超时阈值，降级返回空结构 + 超时提示 |

### 8.3 超支计算异常
| 异常场景 | 兜底策略 |
|----------|----------|
| 进度 = 0 或 NULL | 降级为实际超预算判定：`estimated_overrun = actual_cost - budget` |
| 预算 = 0 | `estimated_overrun` = null，标记「无预算」，不计入超支总额 |
| 实际消耗为负 | 导入时校验拦截，报错拒绝该行 |

### 8.4 导出异常
| 异常场景 | 兜底策略 |
|----------|----------|
| 数据量为空 | 返回错误提示「无数据可导出」，不生成空文件 |
| 文件生成失败 | 返回 500 + 错误信息，前端提示「导出失败，请重试」 |
| 数据量过大（> 10万行） | 限制最大行数或分批导出，返回提示 |

### 8.5 权限异常
| 异常场景 | 兜底策略 |
|----------|----------|
| 未登录 / JWT 过期 | 后端返回 401，前端 Axios 拦截器重定向登录页 |
| 无权限访问（USER 访问导入/导出） | 后端返回 403，前端提示「无权限」 |
| 数据权限越界 | 后端强制按部门/业务线过滤，不报错，静默收敛 |

### 8.6 系统级异常
- 统一异常处理器（`@RestControllerAdvice`）捕获所有未处理异常，返回统一结构 `{code, message, data}`。
- 前端 Axios 响应拦截器统一处理：非 200 状态码弹出 Element Plus `ElMessage.error` 提示。
- 业务异常（校验失败等）返回 HTTP 200 + `code != 0`，前端按 code 分支处理。
