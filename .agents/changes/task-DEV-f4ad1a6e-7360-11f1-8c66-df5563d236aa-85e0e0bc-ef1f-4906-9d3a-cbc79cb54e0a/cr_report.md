## 2. Blocker 问题清单

### B1: [exportRoute.ts] 导出数据硬编码，未反映页面实际展示结果

- **位置**: `src/routes/exportRoute.ts` L11-26 `buildDataRows()`
- **严重级别**: 🔴 Blocker
- **问题描述**: 
  - `hash` case 中 `input = ""` 硬编码为空字符串，导出结果永远是空串的 SHA256，而非用户在页面上实际输入的字符串的哈希值。
  - `bubble-sort` case 中 `bubbleSort([])` 传入空数组，导出结果永远是空数组，而非用户实际排序的数据。
  - 需求明确要求"支持导出各个页面的展示结果"，当前实现完全脱离前端实际数据。
- **修复建议**: 导出接口应接收前端传递的实际数据（通过 POST body 或从服务端缓存/session 中获取），而非在服务端硬编码重新生成。

### B2: [exportRoute.ts] GET 方法不适合传递导出所需数据

- **位置**: `src/routes/exportRoute.ts` L28 `exportRoute.get("/export", ...)`
- **严重级别**: 🔴 Blocker
- **问题描述**: 
  - 导出接口使用 GET 方法 + query params，但冒泡排序需要传入完整数组，哈希计算需要传入原始字符串。GET 请求受 URL 长度限制（通常 2KB-8KB），无法承载大数据量。
  - 即使改为从缓存读取，GET 语义也不适合触发包含副作用或大数据传输的操作。
- **修复建议**: 将导出接口改为 POST 方法，通过 request body 接收 `{ tab, data }` 参数；或设计为 POST + body 传递查询条件，服务端根据条件查询数据后导出。
